# AutoTool

AutoTool 是面向 Windows 的本地可视化自动化工具。通过流程图编排图像识别、鼠标、键盘、判断、循环和脚本调用，通过时间轴编辑已有动作的时间关系。

当前开发版本为 **0.3.2，内部测试版**。1.0.0 之前的版本均为内部测试版本。工程文件为 `.agflow`，运行不需要安装 Python；图标与运行资源随桌面程序打包，支持离线使用。

## 功能

- **流程图与时间轴共用一份工程**：流程连线定义顺序、条件和并行分支；时间轴直接修改已有节点的起点、先后顺序、持续时间及执行轴，不新增节点。
- **简易模式与专家模式**：在设置中切换。简易模式将可安全合并的找图、判断和点击显示成卡片，精简常用参数；专家模式显示完整节点与变量作用域。切换模式保留同一份脚本。
- **主轴与副轴**：主轴由所选分支决定，其他并行分支显示为副轴。各轴独立执行，汇合点等待所有已启动分支完成，主轴可以先于副轴结束。
- **编辑器式工作区**：流程图、时间轴、节点库、参数、变量和日志都可以拖动、停靠、浮动、调整尺寸、关闭和最大化。同一停靠区内的面板通过标签切换。
- **键鼠录制与拆分**：录制可拆成平面流程图，保留长按、组合键、多键重叠、鼠标拖拽、播放速度和重复次数。无需进入片段子编辑器。
- **变量与坐标**：支持全局、脚本局部和执行轴局部变量；坐标用一个 `{x, y, space}` 值管理。找图连接鼠标动作时可以自动创建并绑定坐标输出。
- **运行观测**：显示计划预算与实际输入记录，支持暂停、继续、停止和运行状态悬浮框。停止、异常和并发分支退出时清理自身持有的按键。
- **真实输入与后台点击**：默认使用真实键鼠，可在通用设置启用后台点击，将点击投递至绑定窗口而不移动光标；目标软件是否响应取决于其输入实现。键盘、移动、拖拽和长按仍使用真实输入。

## 使用

### 编辑流程

在左侧节点库选择节点，在画布上连接出口与下一个节点。连线的右键菜单支持“在线上插入节点”和“新增并行分支”。每个普通出口只连接一条路径，条件分支由判断节点表达。

专家模式的“流程”分类提供“并行分支”和“汇合”；简易模式提供“同时执行”，自动创建配对节点。将每个分支接回对应汇合点，随后连接公共后续流程。分支可以包含找图、延时、条件和子脚本调用。

选中节点或完整并行区域后，点击“合并卡片”收纳为一张可命名的卡片，双击原地展开。合并保留底层节点、连线、变量与执行时序，时间轴继续显示内部动作，不转换为录制节点，也不打开子编辑器。合并区域应有明确入口和一条公共后续，外部逻辑分支需先完整纳入选区。

### 编辑时间轴

通过“窗口 → 时间轴”打开面板。拖动其标签可以与流程图组成同一标签组，或停靠、浮动到其他位置。

- 点击条带定位对应流程节点，编辑按键、坐标与持续时间。
- 拖动或编辑数值调整已有动作时间；同轴重排同步修改顺序连线，跨轴移动接回原路径并接入目标轴。条件、循环和跨逻辑区域的结构调整在流程图完成。跨多个按下/松开节点形成的持续区间，可定位相应边界节点后在流程图调整，避免只移动半个持有区间。
- 新增、删除节点及增减并行轴都在流程图完成。时间轴不接受节点库拖入，也不提供重复的新增按钮。
- 找图、等待等操作使用**超时预算**估计时间，不等同于实际耗时；条件提前满足时立即继续。无法确定的时长会标明占位。
- “隐藏超时预算”将预算条带收成标记，保留公共时间刻度、参数与实际超时。
- 编辑视图直接播放预览，支持 0.1–16 倍速与自定义倍率。倍速不改变脚本参数；游标、下方进度条和刻度共用缩放与水平滚动。
- 单轮展示保留原重复次数。运行时在同一视图显示结果，已完成且符合预期的动作绿色，偏差红色，进行中与未执行动作保持独立状态；多轮运行可切换轮次。
- 在“设置 → 通用 → 运行时间容差”调整允许偏差，默认 50ms。找图在超时内提前完成、合法条件分支及暂停均按其实际语义处理，不简单对比预算绝对时刻。运行记录不完整时保留未判定状态。

录制统一通过“拆分节点”转为普通流程，保留微小间隔、持续时间、并发与同刻事件顺序。纯键鼠路径自动使用共同逻辑时钟编排；插入找图或判断后，后续动作等待实际结果，并保留路径间隔，其他轴继续独立执行。画布按主副轴分行，同一起点同列，汇合等待全部已启动分支。旧工程载入时安全转换；含同轴重叠或动态时间的旧时间表保留原时序，避免改变运行行为。新录制无需选择拆分策略。

隐藏超时预算后，播放预览直接跳过只有隐藏预算的空档；其他轴仍有动作或普通延时时继续播放。时间刻度与实际执行保持原工程时间。

### 全局搜索

使用顶部搜索框或 Ctrl+F 搜索当前工程中的全部节点，包含子脚本、未连接节点和合并卡片内部节点。支持名称、类型、按键、变量引用等内容，并可按节点类型筛选搜索结果。选择结果会切换对应脚本、展开卡片，并在流程图与时间轴中同时选中；不隐藏其他流程节点。

### 管理变量

专家模式从“节点库 → 数据 → 变量”进入变量面板，使用作用域选择框管理全局、脚本、区域及各执行轴的变量；面板同时提供工程变量总览。简易模式在节点库中直接提供变量入口，集中管理全局变量，已有局部声明仍然有效。

建议手工变量使用 `用途_含义`，如 `battle_count`、`target_point`。节点输出默认使用 `来源_稳定节点ID_含义`，如 `image_n3_point`、`image_n3_found`。已有名称保持兼容，改名同步更新可见引用，并保留同名局部变量的遮蔽关系。

坐标输出不需要分别管理 X、Y，可直接绑定给鼠标动作，也可使用 `{{image_n3_point.x}}` 和 `{{image_n3_point.y}}`。识别失败会清空坐标，避免误用上次结果。已手工填写的坐标和已有绑定不会被自动连接覆盖。

各并行轴默认写入自己的局部变量。需要共享结果时使用明确的全局变量，不同轴使用不同名称，再在汇合后处理；同时写入同名全局变量会在执行前被拒绝。

### 工作区与设置

“窗口”菜单集中管理六个面板，并提供“重置工作区”。布局和隐藏预算偏好保存在本机，不写入工程。关闭面板不会删除流程数据。

编辑模式从设置切换，状态栏显示 `AutoTool[专家模式]` 或 `AutoTool[简易模式]`。复杂结构无法安全合并时保留原节点，切换不弹提醒。

鼠标和键盘事件作用于系统当前前台环境；窗口绑定不会把真实输入变成后台输入。运行前切换到目标窗口，或在流程中加入窗口激活操作。旧工程的输入方式字段会忽略并在保存时移除。

### 保存与快捷键

| 操作 | 快捷键 |
|---|---|
| 全局搜索 | Ctrl+F |
| 保存 / 另存为 | Ctrl+S / Ctrl+Shift+S |
| 撤销 / 重做 | Ctrl+Z / Ctrl+Y |
| 复制 / 剪切 / 粘贴 | Ctrl+C / Ctrl+X / Ctrl+V |
| 删除选区 | Delete |

画布右键拖动平移，左键框选，Ctrl+点击追加选择。运行、录制和拾取的全局快捷键可在设置中修改或停用。

## 工程格式与执行模型

新保存格式为 **version 6**，兼容读取旧工程。包含平面分叉、汇合或作用域边界的工程需要当前引擎执行。

| 数据 | 用途 |
|---|---|
| `nodes` / `edges` | 完整的原始流程节点与连线 |
| `parallel` / `join` | 配对的分叉与汇合，分支 ID 对应连线出口 |
| `scope` / `join` | 保留展开前的局部作用域，普通编辑无需手工添加 |
| `params.branches` | 轴名、启动偏移及私有变量 |
| `params.timeline` | 相对延迟或精确录制的绝对起点 |
| `variables` / `scripts` | 全局声明、子脚本及各自局部声明 |
| 本机工作区设置 | 面板位置、尺寸、活动标签与预算显示偏好 |

保存文件只包含原始图与必要显示信息；简易卡片、条带、运行事件和画布测量均为派生数据。执行器在副本上将平面图编译为内部执行结构，编译结果不回写工程。

详细技术措施见 [技术改进方案书](AutoTool_技术改进方案书.md)。

## 限制

- Windows 10 / 11，桌面运行时使用 WebView2；安装包内含运行时引导程序，缺少运行时时的安装行为取决于系统环境。
- 每个并行区域最多 16 条轴，同时活动的轴最多 64 条，区域嵌套最多 16 层。
- 精确录制每区域最多 6,000 个动作、120,000 个事件，单轮最长 24 小时，最多重复 1,000 次。
- 一台电脑只有一个真实鼠标光标。普通流程的鼠标操作会仲裁，不能同时处于两个不同位置；精确录制不允许重叠的移动轨迹。
- 同一键被多个来源持有时，只在最后一个来源结束时释放，重叠代表持续持有；多次点按应使用独立动作。
- 计划时间是编排预算；Windows、目标程序、截图识别和命令执行均会影响实际时间，毫秒起点不代表硬实时保证。
- 简易模式保留无法安全合并的复杂节点与原有作用域，不会将任意逻辑强制压成找图卡片。

## 源码与构建

技术栈：Vue 3、TypeScript、Pinia、Vue Flow、Naive UI、Lucide Vue；FastAPI、Python、OpenCV、pynput；Tauri 2、Rust、PyInstaller、NSIS。

```text
frontend/src/components/       面板、节点与参数组件
frontend/src/views/            多文档编辑器
frontend/src/lib/              图迁移、模式投影、变量与时间轴模型
frontend/src/stores/           工程、连接与本机工作区状态
frontend/src-tauri/            原生桌面壳与安装配置
engine/flatgraph.py            平面分叉与作用域编译
engine/executor.py             流程执行与生命周期
engine/parallelflow.py         并行轴与全局写入检查
engine/timeschedule.py         精确键鼠事件计划
engine/inputctl.py             真实输入、持有与清理
assets/                       离线图标和应用图标
tools/                       检查与构建辅助脚本
```

开发需要 Python 3.11+、Node.js 20+、pnpm，以及构建桌面程序所需的 Rust / MSVC 工具链。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r engine/requirements.txt
cd frontend
pnpm install
pnpm dev
```

引擎和前端可以分别通过根目录的 `run_engine.ps1`、`run_frontend.ps1` 启动；桌面开发从 `frontend` 运行 `pnpm tauri dev`。完整打包入口为 `build_desktop.ps1`，包含前端、引擎、桌面壳和 NSIS 安装器。PowerShell 脚本采用 UTF-8 with BOM。
